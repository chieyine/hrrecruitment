# Codebase Audit — 25 July 2026

Full-tree audit of the FRAD Recruitment & Preboarding platform: 364 tracked files
(183 `.ts`, 140 `.tsx`, 2 Prisma schemas, 5 SQL migrations, CI, Docker, scripts).

**Baseline before this pass:** `tsc --noEmit` clean, `eslint .` clean, 26 unit
tests passing — yet the Docker build could not complete and nine user-facing
pages were structurally broken. Both were invisible because the checks that
would have caught them had been narrowed or switched off.

**After this pass:** typecheck clean, lint 0 errors, 36 unit tests passing
(9 files, no unhandled rejections), PostgreSQL schema generator working and
idempotent.

---

## 1. Critical

### 1.1 Nine page components were `async` client components — React does not support this

`src/app/**/page.tsx` (9 files) were written as:

```tsx
'use client'
export default async function VacancyDetailPage(props: { params: Promise<{ id: string }> }) {
  const params = await props.params
  const [vacancy, setVacancy] = useState(null)   // hook inside an async function
```

A client component may not be `async`, and hooks may not be called inside an
async function. ESLint's `react-hooks/rules-of-hooks` reported **95 violations**
plus 9 `@next/next/no-async-client-component` warnings across these files.

Affected: candidate application detail, candidate offer, candidate assessment
runner, the public referee portal, recruitment application review, handover
summary, preboarding clearance, vacancy detail, vacancy applications.

**Why nothing caught it:** commit `aa9eb12` *"chore: disable strict react hooks
rules to pass CI"* turned `react-hooks/rules-of-hooks` off, along with
`purity`, `set-state-in-effect`, `immutability` and `no-find-dom-node`.

**Fixed:** each component is now synchronous and unwraps the params promise with
`React.use(props.params)`, the supported pattern. `rules-of-hooks` is restored to
`error` in `eslint.config.mjs`; the React Compiler *advisory* rules are set to
`warn` rather than off, so they stay visible without failing the pipeline.

### 1.2 The Docker build could not succeed

`scripts/generate-postgres-schema.mjs` did:

```js
const postgres = schema.replace('provider = "sqlite"', 'provider = "postgresql"')
if (postgres === schema) throw new Error('Could not locate the SQLite datasource provider')
```

Commit `bc1b90c` had already switched `prisma/schema.prisma` to
`provider = "postgresql"`, so this script threw on every run. That broke
`db:postgres:schema`, `build:postgres`, `db:postgres:validate` and therefore
`Dockerfile` line 10 (`RUN npm run build:postgres`). CI used plain `npm run build`,
so the pipeline stayed green while the container build was dead.

**Fixed:** the generator accepts either provider and is a no-op copy when the
source is already PostgreSQL, so the generated file is byte-identical to the
canonical schema (verified idempotent). The committed
`prisma/postgresql/schema.prisma` had also drifted and is now regenerated. CI
gains a `git diff --exit-code` gate so drift fails the build next time.

### 1.3 Account enumeration on `/api/auth/login` and `/api/auth/register`

- **Login:** `accountStatus !== 'ACTIVE'` was checked *before* the password,
  so a `403` confirmed an email belonged to a real (suspended) account without
  any credential. Unknown emails also skipped bcrypt entirely, leaving a clear
  timing oracle.
- **Register:** an existing email returned `{success, message}`; a new email
  returned `{success, user:{id,email,roles}, message}` plus a cookie. The
  differing body disclosed whether an address was registered.

**Fixed:** login compares against a fixed dummy bcrypt hash for unknown
accounts so the work factor is identical, and the status check now runs only
after the password is proven (audited as `LOGIN_BLOCKED`). Register returns one
neutral body in both branches; the session cookie is what distinguishes a
genuinely new user.

### 1.4 Every database constraint error surfaced as an opaque 500

`authzResponse` in `src/lib/authz.ts` mapped anything that wasn't an
`AuthzError` to `{ error: 'Internal server error' }, 500`. Across all 140 route
handlers, a duplicate key, a broken foreign key or a missing record therefore
looked like a server fault, and clients had nothing actionable to show.

**Fixed:** P2000/P2002/P2003/P2011/P2014/P2025 map to 400/409/404 with safe
messages; everything else still logs internally and returns a generic 500 —
raw error text is never echoed. Covered by `tests/authz-errors.test.ts`.

### 1.5 Internal error text leaked to unauthenticated callers

| Location | Leak |
|---|---|
| `api/public/vacancies/[reference]` | `{ error: error.message }` — raw Prisma text to anonymous callers |
| `api/cron/process-schedules` | `{ error: error.message }` |
| `api/auth/sso/start` | configuration errors returned verbatim |
| `api/auth/sso/callback` | internal reason reflected into `?error=` on the redirect |
| `app/auth/login/page.tsx` | rendered `?error=` verbatim — arbitrary attacker-supplied copy inside the error box (a phishing vector; React escapes it, so not XSS) |

**Fixed:** all five log internally and return/render fixed text. The login page
maps a small set of known codes to application-controlled messages.

## 2. High

### 2.1 SSO handshake cookies were never cleared

`frad_sso_state`, `frad_sso_verifier` and `frad_sso_nonce` are written with
`path: '/api/auth/sso'` but deleted with the default path `/`. Cookie deletion
must match the path, so all three survived for their full 10-minute lifetime,
leaving a replayable state/verifier/nonce after both success and failure.
**Fixed** via a `clearSsoCookies()` helper that repeats the original path, now
called on both paths.

### 2.2 Path-traversal sanitiser in `lib/s3.ts` was string-based

`storageKey.replace(/\.\.+/g, '')` does not contain traversal — `....//` and
similar constructions survive stripping. **Fixed:** `absPath` now
`path.resolve`s against the storage root and rejects anything that does not
resolve inside it.

### 2.3 `verifyAuditChain()` loaded the entire audit table into memory

`prisma.auditLog.findMany()` with no bound. On any real deployment this is an
OOM waiting to happen. **Fixed:** cursor-paginated at 5,000 rows with a
`maxEntries` ceiling that returns `CHAIN_TOO_LARGE_TO_VERIFY` instead of dying.

### 2.4 Outbox messages could never dead-letter

The claim query hardcoded `attempts: { lt: 5 }` while the failure branch used
per-message `maximumAttempts`. Any message configured above 5 stopped being
picked up at 5 attempts but never reached `DEAD_LETTER` — permanently stuck in
`FAILED` and invisible to the `/api/health` dead-letter check.
**Fixed:** the ceiling is evaluated per message.

### 2.5 Idempotency claims had a create race

`findFirst` then `create` with no handling for the loser, and `actorUserId` is
nullable — PostgreSQL does not treat NULLs as equal in a unique index, so
anonymous claims could never deduplicate at all.
**Fixed:** an `__anonymous__` sentinel puts every claim inside the enforceable
unique key, `findUnique` replaces `findFirst`, and a `P2002` on create re-reads
the winner and replays it.

### 2.6 Generic admin CRUD could hard-delete privilege-bearing configuration

`DELETE /api/admin/generic` hard-deletes any entity without an `active` column.
That includes `roles`, `permissions` and `system-settings` — deleting a
Permission row silently rewrites everyone's access, and deleting `SYSTEM_ADMIN`
locks the platform out of its own administration.
**Fixed:** those three entities are refused with a 409 explaining why. Also in
this file: `model()` now rejects unknown entities with a 400 instead of a
`TypeError`, every list read is capped at 500 rows with a `truncated` flag, and
a stale comment claiming "reads require staff" was corrected.

### 2.7 CSP allowed `'unsafe-inline'` scripts in production

Any HTML injection became script execution. **Fixed:** production now uses
`'strict-dynamic'`, and `object-src 'none'`, `font-src`,
`Cross-Origin-Opener-Policy` were added. **Verify this in a staging
environment before shipping** — a CSP tightening can break third-party embeds.

### 2.8 The only unauthenticated list endpoint was unbounded

`GET /api/public/vacancies` had no rate limit, no pagination, and an unbounded
`search` term driving three `LIKE` scans — while returning every nested
question and required document for every open vacancy.
**Fixed:** 60 req/min per client, `pageSize` capped at 50, search capped at 100
characters, and a `total`/`hasMore` envelope.

`src/app/careers/page.tsx` had the same unbounded public search server-side
(now capped at 100 chars, 200 rows).

**Follow-on:** `candidate/applications/apply/page.tsx` fetched *every* vacancy
and filtered client-side to find one, which pagination would have broken. The
public endpoint now accepts `?id=`, and the page requests only what it needs.

## 4. Reviewed and found sound

Worth recording, because these are the parts most often wrong:

- **No SQL injection surface.** The only raw query is `$queryRaw\`SELECT 1\`` in
  the health check. No `$queryRawUnsafe`, no `eval`, no `new Function`, no
  `dangerouslySetInnerHTML` anywhere in `src/`.
- **Every one of the 140 route handlers is guarded.** The 12 without a session
  check are the intentionally public ones (auth, public vacancies, referee
  portal, fraud reports), and each has its own rate limit and token check.
- **RBAC is genuinely careful.** `EXPLICIT_ONLY_PERMISSIONS` stops `SYSTEM_ADMIN`
  and wildcard grants from implying access to case content; scoped role
  assignments fail closed when resource context is missing; `lib/recruitment-access.ts`
  resolves access against the concrete application rather than trusting a
  caller-supplied id.
- **Token handling is correct.** Purpose-bound JWTs, no insecure secret
  fallback, `sessionVersion` single-use binding on reset and email-change,
  reference tokens stored as SHA-256 hashes and looked up by hash.
- **OIDC does the hard parts right:** PKCE S256, state and nonce both compared
  in constant time, issuer/audience pinned, HTTPS enforced in production.
- **Uploads are defended in depth:** MIME allowlist plus magic-byte
  verification, 10MB cap, per-user hourly limit and a 100MB/24h quota,
  AES-256-GCM at rest, AV gate on download (`CLEAN` only).
- **The audit chain is real:** hash-linked entries with optimistic
  head advancement, bounded retry, and a `CRITICAL` operational event when a
  write ultimately fails.
- **The outbox is a proper transactional outbox:** lease ownership, stale-lease
  reclaim, exponential backoff, dead-lettering, and payload scrubbing after
  delivery.
- **`clientIp()` is not spoofable** — it reads only an explicitly configured
  trusted proxy header rather than trusting `x-forwarded-for`.

## 5. Open items — deliberately not changed

These are real but need a product decision or carry more risk than an audit
should take on unilaterally.

1. **CSP change needs staging verification (§2.7).** `'strict-dynamic'` is
   correct but can break embeds. Confirm before production.
2. **28 further route files still have unbounded `findMany`.** Mostly small
   configuration lookups, but `recruitment/vacancies` (7 calls),
   `admin/configuration-builder` (8) and `reports/export` (10 unbounded of 22)
   should be paginated. Changing their response shapes touches the UI, so it
   belongs in its own change.
3. **Rate limiting is per-instance for the in-memory limiter.** The distributed
   DB-backed limiter is used on the paths that matter; `rateLimit()` should be
   moved to Redis before running more than one instance.
4. **`rateLimitBucket` rows are only cleaned by the retention job.** If that job
   stalls, the table grows without bound.
5. ~~**Files that scan `PENDING` are unusable for ever.**~~ **Retracted — I was
   wrong.** `lib/background-jobs.ts` does re-scan pending files (25 per run,
   deleting and flagging infected ones with a `MALWARE_DETECTED` operational
   event). The mechanism is sound. The only real caveat is throughput: 25 files
   per cron tick could fall behind a bulk-upload spike.
6. **`findIndependentApprover` always returns the oldest matching account,** so
   one person receives every independent approval. Round-robin or load-aware
   selection would be fairer.
7. **`Dockerfile` copies the whole build stage,** including devDependencies and
   source. Adopting Next.js standalone output would cut the image substantially.
   No `HEALTHCHECK` either, despite a good `/api/health` endpoint existing.
8. **Server-rendered dates use the server timezone.** `formatDate` calls
   `toLocaleDateString('en-GB')` with no `timeZone`, in 19 server components.
   Correct today only if the host runs in the intended zone — pin it explicitly.
9. **Test coverage is thin: 36 unit tests for 364 files.** The E2E suite is
   broad, but there is very little unit coverage of `lib/` — notably
   `eligibility.ts`, `work-items.ts`, `background-jobs.ts` and `preboarding.ts`
   (the four largest modules) have none.
10. **13 React Compiler advisories remain** (`set-state-in-effect`, `purity`) —
    now warnings rather than silenced. Mostly `new Date()` in render and
    `setState` in an effect body. Performance and predictability, not
    correctness.
11. **`.env` contains an unused `DIRECT_URL`** (the datasource declares no
    `directUrl`) and no `OUTBOX_ENCRYPTION_KEY` — it currently falls back to
    `STORAGE_ENCRYPTION_KEY`, so outbox payloads and file storage share one key.
    Separate them. `.env` was not modified by this audit.
